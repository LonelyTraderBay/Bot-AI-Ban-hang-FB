# Audit khả năng cưỡng chế UI policy — 06/10/2026

Phạm vi: các gate source spacing, visual tokens, semantic composition, fixture tests, package scripts và CI configuration. Chỉ thêm evidence audit; không sửa UI, checker, contracts hoặc ledger. Kết quả dưới đây là lỗ hổng **cưỡng chế quy định**, không phải tuyên bố đang có lỗi UI tương ứng ở route hiện hành.

## Phương pháp và kết quả đo

- Chạy lại fixture suite hiện có: **24/24 PASS** (10 layout, 5 visual, 9 composition). Log: [existing-fixtures.log](existing-fixtures.log).
- Bộ probe độc lập: **30 trường hợp** = 4 negative controls + 25 bypass probes + 1 false positive. [probe.mjs](probe.mjs) tái hiện bằng AST APIs/strict layout CLI trong thư mục OS temporary và TypeScript compiler host ảo dùng compiler options thật của app.
- Cả 4 negative controls bị đúng gate liên quan từ chối. Điều này kiểm tra các gate đang hoạt động, không phải kết quả từ scanner rỗng.
- **22 probe TSX** lọt cả 3 source gates và typecheck; **1 probe CSS** lọt cả 2 gate liên quan (composition/typecheck không áp dụng CSS). **2 probe còn lại** là bypass visual riêng, đã bị layout gate chặn. Không gọi kết quả này là `npm run verify PASS`: chưa chạy source/domain/lint/browser trên các fixture giả lập.
- Cả 3 gate có thể trả **strict PASS với 0 source file** trên scaffold rỗng. Đây là lỗ hổng kiểm inventory, độc lập với 30 probe.
- `check-layout --report` trả exit 0 dù JSON ghi `FAIL`: đây là hành vi diagnostic có chủ đích, chỉ trở thành bypass khi release runner coi exit 0 là chứng nhận. Package `verify` hiện không dùng `--report`.
- Kết quả/source hashes: [probe-results.json](probe-results.json). Dùng ID Pxx bên dưới để xem nguyên source và expected/observed.

## Những điểm đã có và không nên bỏ

Default CLI modes của cả 3 source gates là strict. Package [verify](../../../../package.json:32) chạy generators/source/boundaries/lint/typecheck/domain/unit/build và cả 3 UI gates; [CI frontend](../../../../../.github/workflows/frontend.yml:38) đã gọi `verify` rồi E2E. Fixture hiện có khóa literal spacing, units px/MUI, canonical bridge factor map, exact-scope exception/stale exception, malformed sources, unknown spread, geometry abuse, direct double-boundary/inset và canonical import aliases ở một số đường.

Không thay các check này bằng blacklist CSS đơn giản, một screenshot hoặc điểm % tự tính. Scope 100% nghĩa là mọi UI change trong inventory phải đi qua contract→owner→source gate→consumer/state render verification→fresh evidence. Một gate PASS hiện hành chỉ xác nhận các pattern gate thực sự hỗ trợ.

## Governance/CI/freshness cần ghi thành task

1. Giữ một policy source; AGENTS/CODING_STANDARDS/catalog liên kết canonical IDs. Không thêm một second token map hoặc checker policy map độc lập chỉ để trông “enterprise”.
2. Bắt pre-edit contract/baseline/profile/source/API/action và output evidence bằng schema/check nhỏ; script hiện hành không cưỡng chế requirement trong văn bản này. Missing fields, source hashes/token/policy version drift, expected route/state chưa chạy phải FAIL/NOT_RUN.
3. Release entry point chỉ chạy strict modes; scanner exit nonzero không được swallow. `--report`, tests skip, threshold nới, ignored file/root đổi phải là policy change có fixture và full verification, không là cách đóng finding.
4. Policy/checker/package/CI/exception thay đổi phải có dedicated review/negative fixture. Repository hiện có CI invocation nhưng audit này chưa xác minh branch protection/required checks/CODEOWNERS/hosted run; **UNKNOWN**, không suy từ YAML rằng AI không thể sửa/bỏ gate.
5. Hash nguồn cuối phải gồm UI owners/consumers, canonical tokens/routes/contracts, checker/tests và policy version. Gắn method/expected/observed cho render/200% text/browser zoom/focus/hit-testing; stale artifact không được dùng để đóng task.
6. Theo Karpathy: mỗi task sửa một invariant đã tái hiện, thêm fixture nhỏ nhất trước, giữ consumer behavior, chạy check cần thiết rồi dừng. Không tạo universal layout engine, form DSL hoặc wrapper cho mọi primitive.

## Giới hạn của kết luận

Các probe là fixtures tổng hợp, không được đưa vào code app. `npm run verify`, full E2E và screenshot route **không chạy lại trong audit này**; chỉ fixture suite 24 tests, strict source probes và virtual TypeScript được chạy. Browser sabotage, screen reader, owner acceptance, hosted CI, branch protection là NOT_RUN/UNKNOWN. Không tăng ledger hoặc ghi production readiness từ kết quả audit/planning.
