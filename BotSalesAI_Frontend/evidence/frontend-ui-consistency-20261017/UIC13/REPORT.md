## Cách nghiệm thu lại từ checkout sạch

1. Kiểm tra branch/ref và SHA theo receipt UIC12; không cherry-pick ngoài chuỗi phụ thuộc.
2. Từ `BotSalesAI_Frontend`, dùng Node/npm theo cấu hình workspace và chạy `npm.cmd run verify` trong PowerShell; lưu exit code cùng stdout/stderr.
3. Chạy built-demo suite bằng `npm.cmd run test:e2e -- --config=playwright.built-demo.config.ts --workers=1 --reporter=line`; giữ route JSON và hash artifact.
4. Chạy `npm.cmd run test:evidence`, doc-link validator UIC11 và hash-manifest verifier; mỗi lần phải ghi lại exit code, số mục kiểm, thời gian, revision và artifact path. Nếu npm child không phân giải được `node`, ghi nguyên trạng lần chạy lỗi và gọi trực tiếp cùng hai lệnh thành phần bằng Node đã pin; chỉ đánh dấu PASS cho lệnh nào thực sự exit 0.
5. So remote ref, PR head, workflow run attempts, check/job results, artifacts và policy API với UIC12. Không tính một run khác SHA làm chứng cho commit này.

`scripts/run-e2e.mjs` thực thi `setup`, build production và `build:demo` trước khi gọi Playwright; cấu hình built-demo mở `dist-demo`, dùng một worker và kiểm tra cả dự án Chromium lẫn Firefox. Vì vậy command ở bước 3 bao gồm build artifact trước khi chạy suite, còn report phải giữ riêng từng stage/exit thay vì chỉ ghi dòng Playwright cuối.

## Khôi phục nếu hồi quy sau khi giao

Đọc remote ref và working tree trước khi khôi phục. Tạo commit revert mới theo thứ tự ngược dependency cho các commit source gây hồi quy; không reset nhánh đã push, không force-push và không xóa log/artifact. Sau revert, chạy lại generator, `npm run verify`, built-demo tests bị ảnh hưởng, S17 owner finalizer/validator và hash/link validators; ghi kết quả rồi push fast-forward. Giữ các commit evidence cần để giải thích sự cố, trừ khi một receipt mới chứng minh rõ phần nào đã được thay thế.
