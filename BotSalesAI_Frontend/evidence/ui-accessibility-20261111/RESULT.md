# UI accessibility follow-up — local evidence

Scope: frontend demo and synthetic data. The Graphite Gold design and existing permission gates are retained. No backend, hosted deployment or physical device is represented by these results.

- The service-case table exposes its existing detail flow from the first cell at narrow widths. The detail dialog presents the customer name when present in the loaded lookup and keeps the customer ID; the ID is the fallback. Its mobile processing action uses the same permission check and fetched case. The lookup is bounded and does not prove names for customers outside the loaded pages.
- Inbox conversation names and previews now wrap rather than truncate at enlarged text. The unread badge remains visible. Pre-edit Firefox desktop native text-only zoom reported eight clipped items in each of two inbox scenarios; the three-scenario 1280×900 desktop retest passed.
- `service-case-test-final.log`: 8 Playwright cases passed on Chrome and Firefox, including 320/390/1440 widths, keyboard entry and lookup fallback. `service-case-regression.log`: 8 detail cases passed across both browsers, including delayed data and 403/404/503.
- `inbox-test-final.log`: 2 Playwright cases passed across both browsers at 390/1440 with text enlarged by a test stylesheet. Paired inbox images are test-stylesheet captures, not native mobile settings.
- `chrome-zoom-post-inbox.log`: five selected scenarios passed with Chrome's native 200% page zoom. `service-case-chrome-zoom-final.log`: a separate native 200% check observed the changed detail-to-processing flow and dialog bounds at 640×360 CSS px. Its screenshot was taken after returning page scroll to zero to avoid a zoomed capture offset.
- `firefox-text-desktop-final.log`: three selected scenarios passed at 1280×900 with actual native text-only zoom 200%. `firefox-text-post-inbox-retry.log`: five selected scenarios passed on Firefox with native text-only 200% at 320–640 CSS px. The first post-fix narrow run is retained as ERROR after four passes when a beforeunload prompt rejected navigation; the complete retry passed.
- Desktop and narrow-width results are not full 61-screen acceptance. Native Firefox text-only resize was not tested on the changed service-case detail. Pre-edit service-case dialog images were captured during their opening transition and do not establish paired visual acceptance for that dialog.
- Narrator could not be controlled because its window had higher Windows integrity; no speech recap was observed. TalkBack, a physical mobile browser, complete role/state coverage and human acceptance remain unverified. See `screen-reader-attempt.md`. S17 remains IN_PROGRESS.
- The first `verify` failed because the shared catalog's MutationButton use count was stale; `verify-before-catalog.log` preserves it. The subsequent run was interrupted after the inbox defect was found; `verify-catalog-interrupted.log` is not a completed verification.
- Final `npm run verify` passed, including 263 Vitest tests and the S17 validator. After recording the final log, `evidence-final.log` passed again with S17 IN_PROGRESS. Generator-owned reports overwritten by verify were restored to their pre-run bytes.
